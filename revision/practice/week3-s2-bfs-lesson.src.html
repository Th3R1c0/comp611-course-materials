Breadth-first search (BFS): fast steps

For each question type: what it means in plain English, the fast steps, and worked examples. The cheatsheet ([GR-4] to [GR-6]) is this same page, condensed.

about 2 exam questionsno calculator needed

2A Plain English: what BFS does

  1. BFS finds the route with the fewest edges (fewest hops) from a start vertex, called the source s, to every other vertex.
  2. It spreads out in rings, like a ripple in a pond. First the source (layer 0). Then everything one edge away (layer 1). Then everything one edge away from layer 1 that has not been seen yet (layer 2). And so on.
  3. A vertex's layer number is exactly its distance from s, counted in edges.
  4. It uses a queue: a waiting line where you join at the back and leave from the front, like a line at a shop. This is called "first in, first out". Taking the front item off is called dequeue. Adding to the back is called enqueue.
  5. It keeps two lists. dist[v] is the number of edges from s to v (it starts as ∞, meaning "not found yet"). prev[v] is the vertex that found v first (it starts as NIL, meaning "nothing").
  6. BFS ignores weights. Every edge counts as 1 hop, whatever number is written on it.

2B Fast steps for each question type

Case A: "In what order are the vertices dequeued (visited)?" Make a queue table.

  1. Write the queue as [s]. Set dist[s] = 0 and prev[s] = NIL.
  2. Take the front vertex off the queue. Call it u. Write it in the "order" list.
  3. Look at u's neighbours in alphabetical order (or the order the question says). For each one that has never been found before: set its dist to dist[u] + 1, set its prev to u, and add it to the back of the queue.
  4. A neighbour that is already in the queue, or already taken off, is skipped.
  5. Repeat from step 2 until the queue is empty. The "order" list is the answer.
  6. Why a queue: because the vertices found first are the closest ones, taking them out first finishes each layer before the next one starts.

Case B: "What is dist[v]?" or "Which vertices are in layer k?" Read it off the table: dist is the layer number. Quick check without the table: it is the smallest number of edges you can walk from s to v.

Case C: "What is prev[v]?"

  1. prev[v] is the vertex that was being taken off the queue when v was first found.
  2. Trap: if two vertices both touch v, the one dequeued earlier wins. The later one sees v is already found and skips it.

Case D: "What is the shortest path from s to v?"

  1. Start at v. Write it down.
  2. Look up prev[v], write it down, and move there. Keep going until you reach s (whose prev is NIL).
  3. You wrote the path backwards, so read it in reverse. The number of hops is dist[v].

Case E: "Is the BFS path also the lightest (smallest total weight)?"

  1. Add up the weights along the BFS path.
  2. Look for a route with more hops but small weights. Add those up.
  3. The answer is usually "no": BFS minimises the number of edges, not the total weight. For weights, use Dijkstra (section 3).

Case F: "What is BFS's running time?" O(V + E) with an adjacency list. Why: every vertex joins the queue at most once (that is the V part), and every edge is looked at once in a directed graph, or twice in an undirected graph (that is the E part). With an adjacency matrix it is O(V²), because finding the neighbours of each vertex means reading a whole row of V boxes.

prev[D] is B, not C. Both B and C touch D, but B was dequeued first, so B found D first.

Example: rebuild the path from A to F (Case D)

Start at F. prev[F] is D. prev[D] is B. prev[B] is A. prev[A] is NIL, so stop. Written backwards: F, D, B, A. Reversed: A, B, D, F.

Path A, B, D, F, which is 3 hops (equal to dist[F] = 3).

Example: is the BFS path the lightest? (Case E)

BFS path A, B, D, F weighs 4 + 4 + 4 = 12. Route A, C, E, F weighs 1 + 2 + 1 = 4. It also has 3 hops.

No. BFS picked a path that weighs 12 when one weighing 4 exists, because BFS counts every edge as 1 and never looks at weights.

Example: running time (Case F)

A graph has 50 vertices and 200 edges, stored as an adjacency list. BFS does about V + E = 50 + 200 = 250 units of work, so it is O(V + E).
