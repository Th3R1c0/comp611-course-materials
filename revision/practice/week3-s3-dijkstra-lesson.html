3A Plain English: what Dijkstra does

  1. Dijkstra finds the route with the smallest total weight from the source s to every vertex. It only works when every weight is 0 or more (no negative numbers).
  2. Like BFS it keeps dist[v] (the best total weight found so far, starting at ∞) and prev[v] (the vertex just before v on that best route, starting at NIL).
  3. It keeps a confirmed set: vertices whose dist is final and will never change. (The lecture calls this set S, which is a different thing from the source vertex s.)
  4. Each round it confirms the unconfirmed vertex with the smallest dist, then relaxes every edge leaving it (see Case A).
  5. To find the smallest dist quickly it uses a priority queue: a to-do list of (vertex, number) pairs that always hands you the pair with the smallest number. Taking it out is called DeleteMin.
  6. Lazy deletion: when a vertex's dist gets better, the course does not change its old pair. It just adds a new pair. The old pair is now stale (out of date). When a stale pair comes out later, the vertex is already confirmed, so it is skipped.
  7. Why it works: with no negative weights, a route can only get heavier as it goes on. So once a vertex has the smallest dist of all unconfirmed vertices, no other route could ever reach it more cheaply.

3B Fast steps for each question type

Case A: "Relax the edge from u to v." What happens? No calculator: one addition

  1. Write down dist[u] (the start of the edge), w(u, v) (the weight of the edge) and dist[v] (the end of the edge).
  2. Add: new = dist[u] + w(u, v).
  3. Compare new with dist[v].
  4. If new is strictly smaller: set dist[v] = new and prev[v] = u. Otherwise (equal or bigger): change nothing.
  5. Why "relax": it loosens an over-high guess down to a better one. It can only ever make dist smaller.

Case B: "In what order are the vertices confirmed?" or "What is dist[] after k steps?" Make a trace table.

  1. Set dist[s] = 0 and every other dist to ∞. Put (s, 0) in the priority queue.
  2. Take out the pair with the smallest number. If that vertex is already confirmed, the pair is stale: write "stale" and take out the next one.
  3. Confirm the vertex. Call it u.
  4. Relax every edge leaving u (Case A). Every time a dist improves, add a new pair (vertex, new dist) to the queue.
  5. Write one table row: the vertex confirmed, the edges that improved, and the queue after.
  6. Repeat from step 2 until the queue is empty. Vertices never reached keep dist ∞.
  7. Trap: the order is by smallest dist, not by when a vertex was first seen. A vertex found later can be confirmed earlier.

Case C: "What is the shortest path, and its cost?" Start at the target and follow prev back to s, then reverse it (exactly like BFS Case D). The cost is dist[target]. Check it by adding the weights along the path.

Case D: "How many times did dist[v] change?" or "Which pairs are stale?" Count the improvements to v in your table. Each improvement after the first leaves one stale pair for v behind in the queue.

  2. Why these numbers: Dijkstra takes out V vertices (DeleteMin) and does at most E improvements. An array takes V steps to find the smallest; a heap takes log V steps for each operation.

Case F: "What happens with a negative edge?" Dijkstra may give a wrong answer, because it may already have confirmed a vertex before the cheaper route through the negative edge is found. Use Bellman-Ford instead (week 4).

3C Worked examples

Example: relax one edge (Case A, Week 3 lab question 3)

dist[a] = 4, dist[b] = 10, and the edge from a to b weighs 3.

Step 1: dist[a] = 4, w(a, b) = 3, dist[b] = 10 Step 2: new = 4 + 3 = 7 Step 3: is 7 smaller than 10? Yes. Step 4: dist[b] becomes 7, prev[b] becomes a.

Then the edge from d to b (dist[d] = 3, weight 2) is relaxed:

new = 3 + 2 = 5. Is 5 smaller than 7? Yes. dist[b] becomes 5, prev[b] becomes d. That is b's second update.

A dist can change many times, as long as the vertex is not confirmed yet.

Example: shortest path from S to T (Case C)

Final dist: S 0, A 3, B 2, C 5, D 6, T 8. prev: A is B, B is S, C is A, D is A, T is C. Follow back from T: T, C, A, B, S. Reverse: S, B, A, C, T. Check: 2 + 1 + 2 + 3 = 8, which matches dist[T].

Example: array or heap? (Case E)

A road map has V = 1,000 vertices and E = 2,000 edges.

Calculator: log₂ 1000 = log(1000) ÷ log(2) = 3 ÷ 0.301, about 10. Array: V² = 1,000 × 1,000 = 1,000,000. Heap: (V + E) × log V = 3,000 × 10 = 30,000.

The heap is much faster here, because the graph is sparse (E is close to V).

Example: a negative edge (Case F, lecture slide)

Dijkstra confirms S (0). Then A gets 2 and B gets 4. It confirms A with 2, the smallest, and A is now final. Later B is confirmed and the edge from B to A gives 4 + (−3) = 1, but A is already final.

Dijkstra reports dist[A] = 2, but the true shortest is 1 (through B). Use Bellman-Ford when an edge is negative.
