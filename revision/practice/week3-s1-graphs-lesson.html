1A Plain English: what a graph is

  1. A graph is a set of dots joined by lines. The dots are called vertices (one is a vertex, also called a node). The lines are called edges.
  2. In an undirected graph an edge works both ways, like a two-way road. In a directed graph each edge has an arrow and works one way only, like a one-way street. "The edge from A to B" means you can go from A to B.
  3. In a weighted graph each edge has a number on it, called its weight (a cost, a distance, a time). w(A, B) means "the weight of the edge from A to B".
  4. V is the number of vertices and E is the number of edges. The lecture writes them as |V| and |E|: the bars just mean "how many".
  5. A path is a route that follows edges, one after another. Its cost is all its weights added up. Its length (number of hops) is how many edges it uses. A cycle is a path that comes back to where it started.
  6. The neighbours of a vertex are the vertices it has an edge to. In a directed graph these are called out-neighbours.
  7. Why we care: before a computer can run BFS or Dijkstra on a graph, it has to store it. There are two ways, and the exam asks which is faster or smaller for a job.

1B Fast steps for each question type

Case A: "Fill in (or read) the adjacency matrix."

  1. Draw a square table. Put every vertex along the top and down the side, in the same order.
  2. The row is where the edge starts. The column is where it ends. So the box in row A, column B is the edge from A to B.
  3. If the edge exists, write its weight (or 1 if the graph has no weights). If it does not exist, write ∞ (weighted) or 0 (unweighted). On the diagonal, from a vertex to itself, write 0.
  4. Undirected trap: each edge goes in two boxes, row A column B and row B column A. So an undirected matrix is a mirror image across the diagonal (the course calls this "symmetric").
  5. Why ∞: "no edge" is like an infinitely long road, so it can never be the shortest way.

Case B: "Write the adjacency list."

  1. Write each vertex once, down the page.
  2. Next to each one, write the pairs (neighbour, weight) for every edge that starts there. If no edge starts there, write a dash.
  3. Undirected: each edge appears in two lists, once for each end.

Case C: "How many storage entries does each one use?"

  1. Count V (vertices) and E (edges).
  2. Matrix: V times V boxes, because it has a box for every possible pair, even pairs with no edge.
  3. List: V plus E entries, one slot per vertex plus one per edge (directed graph). For an undirected graph each edge is stored twice, so it is V plus 2 times E. The big-O answer is still O(V + E).

Case D: "How long does an operation take?" Use the match table, no working needed.

  1. Dense means nearly every pair is joined, so E is close to V². Sparse means few edges, so E is close to V.
  2. Why the matrix checks an edge in one step: it jumps straight to row u, column v. The list has to read through u's neighbours one by one.

Case E: "How many edges does this graph have?"

  1. From a picture: count the lines. Each line is one edge, even in an undirected graph.
  2. From an undirected 0 and 1 matrix: count the 1s, then halve it, because every edge is written twice.
  3. From a directed matrix: count the boxes that have a weight (not 0 on the diagonal, not ∞). Do not halve.

Case F: "Which is faster, O(V to the power 1.5) or O(E)?" The answer is "it depends on the graph". For a dense graph E is about V², which is bigger than V to the power 1.5. For a sparse graph E is about V, which is smaller.
