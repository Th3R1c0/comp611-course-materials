Topic 4 · Growth order and timing tables (sheet [AA-10] [AA-11])

4A Put functions in order

  1. Memorise one line: 1 → log n → n → n log n → n² → n³ → 2ⁿ → n!. Left = slowest growing, right = fastest.
  2. To order a list, drop the numbers in front first, then place each one on the line.
  3. Plain English: log n barely grows (a million is only about 20). n log n is a bit more than n. Powers (n², n³) are much faster. 2ⁿ doubles every time n goes up by 1.

Example: order 5n², 3 log n, 2ⁿ, 100n

Drop numbers: n², log n, 2ⁿ, n. Place them on the line.

log n → n → n² → 2ⁿ

3 log n, 100n, 5n², 2ⁿ

4B Timing tables: "which growth fits?"

  1. Check that n doubles each row (1,000 → 2,000 → 4,000).
  2. Divide each time by the one before it. That's the ratio.
  3. Match the ratio: about 1 (adds a little) → log n · 2 → n · a bit over 2 → n log n · 4 → n² · 8 → n³.
  4. Why: if work is n², doubling n gives 2 × 2 = 4 times the work. For n³ it's 2 × 2 × 2 = 8.

Example: 3 s, 12 s, 48 s as n doubles

Divide each by the one before.

12 ÷ 3 = 4 48 ÷ 12 = 4

Ratio 4, so Θ(n²)

Example: 1 s, 8 s, 64 s as n doubles

Divide.

8 ÷ 1 = 8 64 ÷ 8 = 8

Ratio 8, so Θ(n³)

Example: 2.0 s, 2.1 s, 2.2 s as n doubles

The time only adds 0.1 each time, and the ratio is about 1.

2.1 ÷ 2.0 ≈ 1.05

Θ(log n)

4C "n gets k times bigger. How long now?"

  1. Work out k = new n ÷ old n.
  2. Multiply the time by: k for n · k × k for n² · k × k × k for n³.

Example: Θ(n²) takes 2 s at n = 1,000. How long at n = 3,000?

k = 3,000 ÷ 1,000 = 3. It's n², so multiply by 3 × 3 = 9.

2 s × 9 = 18 s

18 seconds

Example: Θ(n) takes 5 s at n = 100. How long at n = 400?

k = 4. It's n, so multiply by 4.

5 × 4 = 20 s

20 seconds

4D "Which is faster for very large n?"

  1. Ignore the numbers in front completely. Compare the growth on the line.
  2. Whichever grows slower wins (takes fewer steps) for large n, even if it has a huge number in front.

Example: A = 50n vs B = 0.01n²

Drop the numbers: n vs n². n is slower, so A wins for large n.

At n = 1,000,000: A = 50,000,000 B = 10,000,000,000

Topic 5 · Counting steps from pseudocode (sheet [AA-12])

5A How to read any loop question

  1. Find the line inside the deepest loop. It runs the most, so it decides the answer.
  2. Work out how many times each loop goes round, using the pattern table below.
  3. Nested loops (one inside another) → multiply. Loops one after another → add, then keep the biggest.

5B Pattern table: match the loop and read off the answer

Loop shapeTimesGrowth
for i = 1 to nnΘ(n)
for i = 1 to n with for j = 1 to n insiden × nΘ(n²)
for i = 1 to n with for j = i+1 to n inside (each pair once)n(n−1)/2Θ(n²)
for i = 1 to n with for j = 1 to i insiden(n+1)/2Θ(n²)
three nested loops to nn × n × nΘ(n³)
while i > 1: i = i / 2 (or j = j * 2)log nΘ(log n)
a loop to n with a halving loop insiden × log nΘ(n log n)
a loop to n, then a separate loop to nn + n = 2nΘ(n)

Plain English: "j = i + 1 to n" checks every pair once. For n = 5 that's 4 + 3 + 2 + 1 = 10, and 5 × 4 ÷ 2 = 10. Half of n² is still n², because numbers in front are dropped.

5C Exact counts: "how many steps in total?"

  1. Write how many times each line runs next to it.
  2. Loop header (the "for" line): n + 1 times (it checks one extra time to stop). Body: n times. Lines outside loops: 1 each.
  3. Add them up.

Example

Count each line.

1 x = 0 → 1 2 for i = 1 to n → n + 1 3 x = x + A[i] → n 4 return x → 1 total = 1 + (n+1) + n + 1 = 2n + 3

2n + 3, which is Θ(n)

Example: what is count at the end?

for i = 1 to 4 / for j = i+1 to 4 / count = count + 1

n = 4: pairs = 4 × 3 ÷ 2 = 6 (i=1: 3, i=2: 2, i=3: 1, i=4: 0 → 3+2+1 = 6)

Topic 6 · Best and worst cases, Fibonacci (sheet [AA-13] [AA-14])

6A Memorise this table

AlgorithmBest caseWorst case

Insertion sortΘ(n): already sortedΘ(n²): reverse order
Merge sortΘ(n log n): any inputΘ(n log n): any input

"Same best and worst?" → merge sort (and selection/bubble). "Depends on input order?" → insertion sort, linear search.

6B Insertion sort shifts

  1. Insertion sort takes each item and slides it left into place, like sorting cards in your hand. Each one-place slide is a shift.
  2. Already sorted: 0 shifts, but still Θ(n), not Θ(1), because it must look at every item once.
  3. Reverse order: shifts = n × (n − 1) ÷ 2.
  4. Any list: shifts = the number of pairs that are in the wrong order.

Example: reversed list of 5

n = 5

5 × 4 ÷ 2 = 10 shifts

10

Example: [3, 1, 2]

Count pairs in the wrong order (a bigger number before a smaller one).

(3,1) wrong · (3,2) wrong · (1,2) fine

2 shifts

6C Early return and Fibonacci

  1. If a loop can stop early (a return inside the loop), the time depends on the values, so there's no single Θ. Say O(worst) and Ω(best).
  2. Fibonacci (0, 1, 1, 2, 3, 5, 8…, where each is the sum of the two before): naive recursion is exponential because it recalculates the same numbers again and again.
  3. Fix by storing answers (memoisation) or using a loop: O(n). Matrix exponentiation: O(log n).
  4. Trap: recursion itself isn't slow. Binary search is recursive and only log n.
