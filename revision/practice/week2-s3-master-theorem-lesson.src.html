Topic 4 · The Master Theorem (sheet [DC-8] to [DC-10])

4A Fast steps: "Which case applies, and what is T(n)?"

Calculator: yes for step 2 only.

  1. Step 1: read off a, b and f(n) from T(n) = aT(n/b) + f(n). a is the number of calls (at least 1), b is what n is divided by (more than 1), and f(n) is the extra work.
  2. Step 2: work out p. On the calculator, type log a ÷ log b. This is the fastest way. (Or look it up in the match table [DC-M] on the cheatsheet.)
  3. Step 3: find k, the power of f(n). The power of n² is 2, the power of n is 1, the power of the square root of n is 0.5, and a constant like 1 has power 0.
  4. Step 4: compare k with p.
    If k is smaller than p, it is Case 1 and T(n) = Θ(n^p). The leaves win.
    If they are equal, it is Case 2 and T(n) = Θ(n^p × log n). Every level costs the same.
    If k is bigger, it is Case 3 and T(n) = Θ(f(n)). The top wins.
  5. Case 3 only: also check the regularity condition. On the calculator, type a ÷ b^k. If the answer is less than 1, it holds. (For ordinary powers of n it always does in Case 3.)
  6. Why: n^p is the total work of all the leaves at the bottom of the recursion tree, and f(n) is the work at the top. Whichever is bigger decides the answer. If they are equal, every level costs the same, so you multiply by the number of levels, log n.

4B Worked examples, one per case

Case 1: T(n) = 8T(n/2) + n² (lecture example 1)

Calculator: yes

Step 1 a = 8, b = 2, f(n) = n² Step 2 p = log 8 ÷ log 2 = 3 (calculator) Step 3 k = 2 (the power of f) Step 4 2 is smaller than 3, so Case 1

T(n) = Θ(n³)

Case 2: T(n) = 2T(n/2) + n (merge sort)

Calculator: yes

Step 1 a = 2, b = 2, f(n) = n Step 2 p = log 2 ÷ log 2 = 1 (calculator) Step 3 k = 1 (the power of f) Step 4 1 equals 1, so Case 2

T(n) = Θ(n¹ × log n) = Θ(n log n)

Case 2 with p = 0: T(n) = T(n/2) + 1 (binary search)

Calculator: yes

Step 1 a = 1, b = 2, f(n) = 1 (a constant) Step 2 p = log 1 ÷ log 2 = 0 (calculator) Step 3 k = 0 (the power of f) Step 4 0 equals 0, so Case 2

T(n) = Θ(n⁰ × log n) = Θ(log n)

Case 3: T(n) = 7T(n/2) + n³ (lab 2)

Calculator: yes

Step 1 a = 7, b = 2, f(n) = n³ Step 2 p = log 7 ÷ log 2 = 2.807 (calculator) Step 3 k = 3 (the power of f) Step 4 3 is bigger than 2.807, so Case 3 Step 5 regularity: type 7 ÷ 2^3 = 0.875, less than 1 ✓

T(n) = Θ(n³)

Decimal p: T(n) = 3T(n/2) + n (Karatsuba)

Calculator: yes

Step 1 a = 3, b = 2, f(n) = n Step 2 p = log 3 ÷ log 2 = 1.585 (calculator) Step 3 k = 1 (the power of f) Step 4 1 is smaller than 1.585, so Case 1

T(n) = Θ(n^1.585), written Θ(n^(log₂ 3))

4C When the Master Theorem does NOT apply

No calculator needed

  1. f(n) is only a log away from n^p, for example f(n) = n log n or n ÷ log n when p = 1. A log is too small a difference: the cases need a whole power of n (or a decimal power) between them. This is a "gap" between the cases.
  2. The shape is wrong: a is less than 1, b is not more than 1, the number of calls depends on n, or f(n) is negative.
  3. Case 3 looks right but the regularity condition fails.
  4. Course answers: the lecture and class examples say T(n) = 2T(n/2) + n log n as "Master Theorem does not apply". If a question mentions the extended Case 2 (the logᵏ n version), its answer is Θ(n log² n). The lab solution gives both.
  5. Trap: f(n) = log² n (log n times log n) with p = 0.682 (lab 2 (e)) does apply: any log grows slower than any power, so it counts as smaller. That makes it Case 1, so the answer is Θ(n^0.682).

4D Karatsuba: why fewer subproblems is faster

  1. Multiplying two n-digit numbers the school way is like splitting each number in half and doing 4 half-size multiplications: T(n) = 4T(n/2) + Θ(n). p = log 4 ÷ log 2 = 2, so it is Case 1 and the answer is Θ(n²).
  2. Karatsuba uses an algebra trick to need only 3: T(n) = 3T(n/2) + Θ(n). p = log 3 ÷ log 2, about 1.585, so it is Case 1 and the answer is Θ(n^1.585).
  3. Why one fewer call matters so much: the saving happens at every level, so the number of leaves drops from n² to n^1.585. Fewer subproblems give a smaller p, which gives a smaller answer.
  4. Calculator: yes Speed-up estimate for n = 10,000. Step 1: type 10000^2 = 100,000,000. Step 2: type 10000^1.585, which is about 2,187,000. Step 3: divide the first by the second, which is about 46. So Karatsuba is about 46 times faster.
  5. Here n is the number of digits (or bits), not the size of the number.
