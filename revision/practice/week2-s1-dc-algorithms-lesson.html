Start here: words and symbols (sheet [DC-0])

0 Words you need for this week

  1. Recursive means a function that calls itself on a smaller piece of the problem. Each of those calls is a recursive call.
  2. A subproblem is one of the smaller pieces. Sorting the left half of a list is a subproblem of sorting the whole list.
  3. The base case is the size where the function stops splitting and just answers directly (e.g. a list of 1 item is already sorted). Without it, the function would call itself forever.
  4. T(n) is read "T of n": the time (number of steps) the algorithm takes on an input of size n. T(n/2) is "the time for an input half the size".
  5. A recurrence is an equation that describes T(n) using T of a smaller size. Example: T(n) = 2T(n/2) + n says "the time for n = two half-size jobs, plus n extra steps".
  6. ⌊x⌋ (floor) means "round down". ⌊7/2⌋ = ⌊3.5⌋ = 3.
  7. log₂ n means "how many times can I halve n until I reach 1?" log₂ 8 = 3 because 8 → 4 → 2 → 1 is 3 halvings. More generally log_b a means "what power of b gives a?": log₃ 9 = 2 because 3 × 3 = 9.
  8. Powers of n: n⁰ = 1 (a constant), n¹ = n, n² = n × n. A decimal power sits in between: n^1.58 grows faster than n but slower than n². n^0.5 is the square root of n.
  9. Θ means "grows exactly like" (from week 1, [AA-6]). Θ(1) means "a fixed number of steps", no matter how big n is.
Topic 1 · The divide and conquer idea and its three algorithms (sheet [DC-1] to [DC-4])

1A The three steps (definition questions)

  1. Divide: split the problem into smaller subproblems of the same kind.
  2. Conquer: solve each subproblem by calling the same function on it (recursively). When a subproblem is small enough (the base case), solve it directly.
  3. Combine: join the subproblem answers into the answer for the whole problem.
  4. Why it helps: small problems are easy, and if splitting and joining are cheap, the total work can be much less than the obvious method.

1B Trace binary search

  1. The list must be sorted. Write the positions (indexes) under the values.
  2. mid = ⌊(low + high) ÷ 2⌋ (round down). Look at A[mid], the value at that position.
  3. If A[mid] = target: found. If target is smaller: high = mid − 1 (keep the left part). If bigger: low = mid + 1 (keep the right part).
  4. Repeat. If low becomes bigger than high, the target isn't there.
  5. Why it's fast: each look throws away half of what's left, so it takes about log₂ n looks: Θ(log n). For 1,000 items that's only about 10 looks.

Example: A = [3, 7, 11, 15, 19, 24, 30] (positions 0 to 6), target 24

low=0 high=6 mid=⌊6/2⌋=3 A[3]=15 24 bigger → low=4 low=4 high=6 mid=⌊10/2⌋=5 A[5]=24 found at position 5

Values checked: 15, then 24

1C Trace MERGE (the combine step of merge sort)

  1. You have two lists that are already sorted, L and R. Point at the front of each.
  2. Compare the two front items. Take the smaller one (if equal, take L's), add it to the result, and move that pointer along. That's one comparison.
  3. When one list is empty, copy the rest of the other list across. No more comparisons are needed for that.
  4. Count comparisons = how many items were taken by comparing (not copied at the end).
  5. Why merge sort is Θ(n log n): merging costs about n steps at every level, and there are log₂ n levels of halving.

Example: L = [2, 5, 8], R = [3, 7] (from the lecture)

2 vs 3 → take 2 [2] 5 vs 3 → take 3 [2,3] 5 vs 7 → take 5 [2,3,5] 8 vs 7 → take 7 [2,3,5,7] R empty → copy 8 [2,3,5,7,8]

4 comparisons, result [2, 3, 5, 7, 8]

1D Trace fast exponentiation POWER(x, n)

  1. It works out xⁿ (x multiplied by itself n times).
  2. If n = 0, return 1 (base case).
  3. Otherwise first work out y = POWER(x, ⌊n/2⌋). So the n values go: n, then half of n rounded down, and so on down to 0.
  4. If n is even, return y × y. If n is odd, return x × y × y.
  5. Why it's fast: the normal way needs n − 1 multiplications. This halves n each call, so about log₂ n calls: Θ(log n). For n = 1,000: 999 multiplications vs about 10 calls.

Example: POWER(3, 13) (from the lecture)

n values: 13 → 6 → 3 → 1 → 0 (base case, returns 1) n=1 odd : 3 × 1 × 1 = 3 n=3 odd : 3 × 3 × 3 = 27 n=6 even: 27 × 27 = 729 n=13 odd : 3 × 729 × 729 = 1,594,323

The calls are 13, 6, 3, 1, 0 (5 calls). Answer 3¹³ = 1,594,323
