4A Fast steps: "Which case applies, and what is T(n)?"

  1. Read off a, b and f(n) from T(n) = a T(n/b) + f(n). a = number of calls (at least 1), b = how much smaller (more than 1), f(n) = the extra work.
  2. Work out p = log_b a ("what power of b gives a?"). Use the table below, or on the calculator: log(a) ÷ log(b).
  3. Find the power of f(n): n² → 2, n → 1, √n → 0.5, 1 (a constant) → 0.
  4. Compare the power of f with p:
    f's power smaller than p → Case 1 → T(n) = Θ(n^p) (the leaves win)
    equal → Case 2 → T(n) = Θ(n^p × log n) (every level costs the same)
    f's power bigger than p → Case 3 → T(n) = Θ(f(n)) (the top wins)
  5. Case 3 only: also check the "regularity condition": a × f(n/b) must be at most c × f(n) with c less than 1. For f = n^k this is a ÷ bᵏ, so just check that a ÷ bᵏ is less than 1. (For ordinary powers of n it always is in Case 3.)
  6. Why: n^p is the total work of all the leaves at the bottom of the recursion tree, and f(n) is the work at the top. Whichever is bigger decides the answer. If they are equal, every level costs the same, so you multiply by the number of levels, log n.

4B Worked examples, one per case

Case 1: T(n) = 8T(n/2) + n² (lecture example 1)

a = 8, b = 2, f(n) = n² p = log₂ 8 = 3 power of f = 2, which is smaller than 3 → Case 1

T(n) = Θ(n³)

Case 2: T(n) = 2T(n/2) + n (merge sort)

a = 2, b = 2, f(n) = n p = log₂ 2 = 1 power of f = 1, equal to 1 → Case 2

T(n) = Θ(n¹ × log n) = Θ(n log n)

Case 2 with p = 0: T(n) = T(n/2) + 1 (binary search)

a = 1, b = 2, f(n) = 1 p = log₂ 1 = 0 power of f = 0 (a constant is n⁰), equal → Case 2

T(n) = Θ(n⁰ × log n) = Θ(log n)

Case 3: T(n) = 7T(n/2) + n³ (lab 2)

a = 7, b = 2, f(n) = n³ p = log₂ 7 ≈ 2.807 power of f = 3, bigger → Case 3 regularity: a ÷ bᵏ = 7 ÷ 2³ = 7/8, less than 1 ✓

T(n) = Θ(n³)

Decimal p: T(n) = 3T(n/2) + n (Karatsuba)

a = 3, b = 2, f(n) = n p = log₂ 3 ≈ 1.585 power of f = 1, smaller → Case 1

T(n) = Θ(n^1.585), written Θ(n^(log₂ 3))

4C When the Master Theorem does NOT apply

  1. f(n) is only a log away from n^p, for example f(n) = n log n or n ÷ log n when p = 1. A log is too small a difference: the cases need a whole power of n (or a decimal power) between them. This is a "gap" between the cases.
  2. The shape is wrong: a is less than 1, b is not more than 1, the number of calls depends on n, or f(n) is negative.
  3. Case 3 looks right but the regularity condition fails.
  4. Course answers: the lecture and class examples say T(n) = 2T(n/2) + n log n → "Master Theorem does not apply". If a question mentions the extended Case 2 (the logᵏ n version), its answer is Θ(n log² n). The lab solution gives both.
  5. Trap: f(n) = log² n (log n times log n) with p = 0.682 (lab 2 (e)) does apply: any log grows slower than any power, so it counts as smaller → Case 1 → Θ(n^0.682).

4D Karatsuba: why fewer subproblems is faster

  1. Multiplying two n-digit numbers the school way is like splitting each number in half and doing 4 half-size multiplications: T(n) = 4T(n/2) + Θ(n) → p = log₂ 4 = 2 → Case 1 → Θ(n²).
  2. Karatsuba uses an algebra trick to need only 3: T(n) = 3T(n/2) + Θ(n) → p = log₂ 3 ≈ 1.585 → Case 1 → Θ(n^1.585).
  3. Why one fewer call matters so much: the saving happens at every level, so the number of leaves drops from n² to n^1.585. Fewer subproblems → smaller p → smaller answer.
  4. Speed-up estimate: divide the two step counts. For n = 10,000: n² = 100,000,000 and 10,000^1.585 ≈ 2,190,000, so Karatsuba is about 46 times faster.
  5. Here n is the number of digits (or bits), not the size of the number.
