Disjoint sets (union-find): fast steps

About 2 exam questions and 5 marks. You follow arrows up to the top, and join two trees with one simple rule. The cheatsheet ([DS-1] to [DS-5]) is this page, condensed.

about 2 exam questions, 5 marksCalculator: not needed

A Plain English: what disjoint sets are

  1. Disjoint sets are groups that never share an item. Every item is in exactly one group. Example: {1, 2, 5}, {3, 4} and {6} are disjoint sets.
  2. Each group has one member chosen as its representative (its "name tag"). Two items are in the same group exactly when they have the same representative.
  3. There are three operations. MAKE-SET(x) makes a new group holding only x. FIND-SET(x) returns the representative of x's group. UNION(x, y) joins x's group and y's group into one.
  4. The fast way to store them is a disjoint-set forest: each group is a tree, every item has an arrow to its parent, and the root (the top, which is its own parent) is the representative.
  5. Uses: finding connected components of a graph (UNION the two ends of every edge), and the cycle check in Kruskal's algorithm (week 7): an edge makes a cycle exactly when FIND-SET gives the same root for both ends.

B Fast steps for each question type

Case A: "What does FIND-SET(x) return?" Follow the arrows up from x until you reach the root. The root is the answer. The nodes you pass are the find path.

Case B: "What changes after FIND-SET(x) with path compression?"

  1. Write the find path from x up to the root.
  2. Every node on that path now points straight at the root.
  3. Nodes that already pointed at the root do not change. Nodes not on the path do not change. Ranks do not change.

Case C: "What happens after UNION(x, y) with union by rank?" Each root stores a rank, which is roughly the height of its tree. A new item has rank 0.

  1. Find the two roots: rx = FIND-SET(x) and ry = FIND-SET(y). If they are the same, nothing happens.
  2. If the ranks are different: the root with the smaller rank goes under the root with the bigger rank. No rank changes.
  3. If the ranks are equal (a tie): rx goes under ry (the root of the second argument becomes the parent), and ry's rank goes up by 1. Only a tie ever raises a rank.
  4. Why: hanging the shorter tree under the taller one keeps trees short, so FIND-SET stays fast.

Case D: "Running time?"

Way of storingTime for m operations on n items
Forest, no tricksO(m n): trees can become one long chain
Forest, union by rank onlyO(m log n)
Forest, union by rank and path compressionO(m α(n)), almost O(m)
Linked lists with weighted union (append the shorter list)O(m + n log n)

α(n) is the inverse Ackermann function. It grows so slowly that it is at most 4 for any real n, so in practice each operation is almost constant time.

Case E: "Linked list version: costs?" Each group is a list, and the head is the representative. MAKE-SET and FIND-SET are O(1) (every node points back to its list). UNION appends one list to the other and must update every moved node, so it costs the length of the moved list. Without care, n − 1 unions can cost about n²/2 in total.

C Worked examples

The week 11 lab forest. Arrows point from a node to its parent. Root 6 has rank 3.

Example: FIND-SET (Case A)

FIND-SET(1): 1 goes to 2, 2 goes to 4, 4 goes to 6, and 6 is the root. FIND-SET(8): 8 goes to 7, 7 goes to 6.

Both return 6, so 1 and 8 are in the same set.

Example: path compression (Case B)

FIND-SET(1) with path compression. The find path is 1, 2, 4, 6. Node 1 now points to 6 (it pointed to 2) and node 2 now points to 6 (it pointed to 4). Node 4 already pointed to 6. Node 3 is not on the path, so it still points to 4. Rank of 6 stays 3.
