1A Plain English: what a greedy algorithm is

  1. A greedy algorithm builds the answer one choice at a time. At each step it takes whatever looks best right now, and it never goes back to change a choice.
  2. Compared with the other methods: divide and conquer splits into several subproblems, dynamic programming solves every subproblem and keeps the best, and greedy makes one choice and solves only one smaller problem.
  3. Greedy does not always give the best answer. Example: coins worth 1, 3 and 4, and you must pay 6 with as few coins as possible. Greedy takes the biggest coin first: 4, then 1, then 1, which is 3 coins. The best is 3 and 3, which is 2 coins.
  4. Greedy is correct only when the problem has two properties. Greedy choice property: some best answer contains the greedy choice. Optimal substructure: after that choice, the rest of a best answer is a best answer to the smaller problem.
  5. Ways to prove a greedy algorithm correct: an exchange argument (swap one piece of a best answer for the greedy choice and show it is still best), staying ahead (show greedy is at least as good after every step), and for MSTs, the cut property.

1B Interval scheduling: fast steps

You have one room and many activities, each with a start time and a finish time. Pick the most activities that do not overlap. An activity written [4, 6) starts at 4 and finishes at 6, and another activity may start at exactly 6.

Case A: "Which activities does the greedy algorithm pick?"

  1. Sort the activities by finish time, earliest first.
  2. Pick the first one. Remember its finish time.
  3. Go down the list. Pick an activity only if it starts at or after the last picked finish time, then update that finish time. Otherwise skip it.

Case B: "Which rule is NOT always optimal?" Earliest start time, shortest length, and fewest conflicts can all fail. Only earliest finish time is always optimal. Counterexample for earliest start: [0, 10) starts first and blocks [1, 2), [2, 3) and [3, 4).

Case C: "Running time?" O(n log n), because sorting dominates. If the activities are already sorted by finish time, it is O(n).

Section 2: Minimum spanning trees and Prim's algorithm

2A Plain English: what a minimum spanning tree is

  1. The graph is undirected and weighted. A spanning tree uses some of the edges to connect every vertex with no cycles (no loops).
  2. A minimum spanning tree (MST) is a spanning tree whose edge weights add up to the smallest total.
  3. Facts that are asked as true or false: a spanning tree on V vertices has exactly V − 1 edges. Removing any tree edge disconnects it. Adding any extra edge makes a cycle. If all weights are different, the MST is unique.
  4. Cut property: split the vertices into two groups. The lightest edge crossing between the groups is in every MST (when weights are different), so it is always safe to add.
  5. Cycle property: the heaviest edge on any cycle is in no MST.

2B Prim's algorithm: fast steps

Prim grows one tree outward from a start vertex, like a cloud spreading.

Case D: "In what order does Prim add vertices or edges?"

  1. Put the start vertex in the tree.
  2. Look at every edge that joins a vertex in the tree to a vertex not yet in the tree.
  3. Add the lightest of those edges, and the new vertex it reaches.
  4. Repeat until every vertex is in. You add V − 1 edges.
  5. Edges between two vertices already in the tree are ignored, since they would make a cycle.

Case E: "Running time?" O(E log V) with an adjacency list and a binary heap (priority queue). O(V²) with an adjacency matrix and a simple search for the smallest. The start vertex does not change the total weight.

Section 3: Kruskal's algorithm

3A Kruskal's algorithm: fast steps

Kruskal does not grow from one vertex. It looks at all edges from lightest to heaviest and keeps any edge that does not make a cycle. Small groups of joined vertices (called clusters or components) slowly merge into one tree.

Case F: "In what order does Kruskal accept edges?" or "Which edge is rejected?"

  1. Sort all edges by weight, smallest first.
  2. Take the next edge. If its two ends are already connected by edges you have accepted, reject it (it would make a cycle). Otherwise accept it.
  3. Stop when you have V − 1 edges.

Case G: "Running time?" O(E log V) using a disjoint set forest (union-find, week 11), because sorting the edges dominates. With a simple label array it is O(E log V + V²).

Case H: "Prim or Kruskal: what is the difference?" Prim grows one tree from a start vertex. Kruskal sorts all edges and merges a forest of clusters. Both give an MST with the same total weight, and the same edges when all weights are different.
