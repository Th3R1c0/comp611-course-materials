Binary search trees: fast steps

About 3 exam questions and 6 marks, and the easiest topic left. Every question is "go left if smaller, right if bigger" or "list the keys in a set order". The cheatsheet ([BS-1] to [BS-6]) is this page, condensed.

about 3 exam questions, 6 marksCalculator: not needed

A Plain English: what a binary search tree is

  1. A binary tree is made of nodes. Each node holds a number (its key) and has at most two children: a left child and a right child. The top node is the root. A node with no children is a leaf. NIL means "no child here".
  2. A binary search tree (BST) follows one rule at every node: everything in its left part (left subtree) is smaller, and everything in its right part is bigger.
  3. The height h is the number of edges (lines) on the longest path from the root down to a leaf. A tree with only a root has height 0.
  4. Almost every operation walks one path from the root downward, so it takes O(h) time. If the tree is bushy (balanced), h is about log n, which is fast. If the keys were inserted in sorted order, the tree is one long chain and h is n − 1, which is slow, so the worst case is O(n).

B Fast steps for each question type

Case A: "Give the inorder, preorder or postorder walk." The name says when the root is written.

  1. Inorder is left, root, right. For a BST this is just the keys sorted smallest to largest, so you do not need to walk it at all.
  2. Preorder is root, left, right: write the node before its children. The first key is always the root.
  3. Postorder is left, right, root: write the node after both its children. The last key is always the root.
  4. Trick for pre and post: trace around the outside of the tree anticlockwise starting at the root. Preorder writes each node when you pass its left side. Postorder writes each node when you pass its right side.

Case B: "Search for k", "minimum" or "maximum". Search: start at the root; if k is smaller go left, if bigger go right, until you find k or fall off (not found). Minimum: keep going left. Maximum: keep going right.

Case C: "Successor of x" (the next bigger key).

  1. If x has a right child: go right once, then left as far as you can.
  2. If not: climb up until you step up from a left child. That parent is the successor.
  3. Quick check: it is the key that comes straight after x in the sorted list. Predecessor is the mirror (the key just before x).

Case D: "Insert k" or "Draw the tree after inserting these keys". Search for k as in Case B. Where you fall off the tree, attach k there as a new leaf. Nothing else moves. The first key inserted is the root, so the order of insertion decides the shape.

Case E: "Delete z". Count z's children.

  1. No children: just remove it.
  2. One child: that child moves up into z's place (with everything under it).
  3. Two children: find z's successor (go right once, then left as far as possible). Put the successor's key in z's place, and remove the successor from its old spot (it has at most a right child, which moves up).

Case F: "Running time?" Search, insert, delete, minimum, maximum, successor and predecessor are all O(h): O(log n) when balanced, O(n) in the worst case (a chain). A full inorder, preorder or postorder walk is Θ(n), because it visits every node once whatever the shape.

C Worked examples (using the tree above)

Example: the three walks (Case A)

Inorder (sorted): 20, 30, 40, 45, 50, 60, 70, 75, 80 Preorder: 50, 30, 20, 40, 45, 70, 60, 80, 75 Postorder: 20, 45, 40, 30, 60, 75, 80, 70, 50

Preorder starts with the root 50. Postorder ends with the root 50.

Example: successor (Case C)

Successor of 70: it has a right child 80. Go right to 80, then left as far as possible: 75. Successor of 45: no right child. Climb: 45 is the right child of 40, keep climbing. 40 is the right child of 30, keep climbing. 30 is the LEFT child of 50, so stop: 50.

Successor of 70 is 75. Successor of 45 is 50. Check with the sorted list: 75 comes after 70, and 50 comes after 45.

Example: insert 65 (Case D)

65 > 50, go right to 70. 65 < 70, go left to 60. 65 > 60, go right: empty.

65 becomes the right child of 60.

Example: the three delete cases (Case E)

Delete 20: no children, just remove it. Delete 40: one child (45), so 45 moves up and becomes the right child of 30. Delete 50: two children. Successor = right once (70), then left as far as possible (60). 60 takes the root's place. 70's left child becomes empty.

After deleting 50 the root is 60, with 30 on its left and 70 on its right.
