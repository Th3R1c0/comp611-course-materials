Dynamic programming, LIS and edit distance: fast steps

About 5 exam questions and 12 marks. Almost every question is "fill in a small table by counting". The cheatsheet ([DP-0] to [DP-9]) is this page, condensed.

1A Plain English: what dynamic programming is

  1. Dynamic programming (DP) solves a big problem by solving smaller versions of it first, writing each answer in a table, and reusing those answers instead of working them out again.
  2. It works when the small problems overlap, which means the same small problem is needed again and again. Writing the answer down once saves all that repeated work.
  3. Divide and conquer (week 2) also splits a problem into smaller ones, but there the pieces are independent (they never share work), so it goes top down. DP pieces overlap, so DP fills the table from the smallest problem upward, which is called bottom up.
  4. Optimal substructure means the best answer to the big problem is built out of best answers to smaller problems. Example: any piece of a shortest path is itself a shortest path. Both D&C and DP need this.
  5. The four steps of DP from the lecture: 1. split into subproblems named by a number (the parameter). 2. write the base case, the smallest problem you can answer straight away. 3. write the recurrence, the rule that builds a bigger answer from smaller ones. 4. fill the table bottom up.
  6. Bellman-Ford and Floyd-Warshall (week 4) are also DP algorithms. That is a common true or false question.

1B Fast steps: DP idea questions

Case A: "Which property makes DP a good choice?" Answer: overlapping subproblems plus optimal substructure.

Case B: "How is DP different from divide and conquer?" Answer: D&C subproblems are independent and solved top down. DP subproblems overlap, so their answers are stored in a table and it is filled bottom up.

Case C: "Which is the base case / recurrence?" The base case is the smallest problem with an answer you can write straight away (like "a list of one number has LIS 1"). The recurrence is the line that uses earlier table entries.

Section 2: Longest increasing subsequence (LIS)

2A Plain English: what LIS means

  1. A subsequence is some of the numbers of a list, kept in their original order, but you are allowed to skip numbers. They do not have to be next to each other.
  2. An increasing subsequence is one where every number is bigger than the one before it. Equal numbers do not count as increasing.
  3. The LIS is the longest increasing subsequence. There can be more than one with the same longest length.
  4. Example: in the list 5, 2, 8, 6, 3, 6, 9, 7, the numbers 2, 3, 6, 9 are an increasing subsequence of length 4. The numbers 5, 3, 9 are not increasing, because 3 is smaller than 5. The numbers 8, 5 are not a subsequence at all, because in the list the 5 comes before the 8, and you may not change the order.
  5. The DP table is one row called L. L(i) means "the length of the longest increasing subsequence that ends exactly at the number in position i".

2B Fast steps for each LIS question type

Case A: "Fill in the L values" (the most common question). Go left to right. For each number:

  1. Look at every number to its left that is smaller than it.
  2. If there are none, write L = 1 (the number on its own).
  3. Otherwise, find the biggest L among those smaller numbers, and write that plus 1.
  4. Why: you are taking the best increasing run that ends at a smaller earlier number, and adding this number on the end.

Case B: "What is the length of the LIS?" It is the biggest number in the L row. It is not always the last L.

Case C: "Which of these is a longest increasing subsequence?"

  1. Start at a position with the biggest L. Write its number down.
  2. Move left to a smaller number whose L is exactly one less. Write it down. Repeat until you reach an L of 1.
  3. You wrote it backwards, so read it in reverse. Quick check for an option: it must be in the original order, strictly increasing, and as long as the biggest L.

Case D: "Running time and space?" Time O(n²), because each of the n numbers looks back at up to n earlier numbers (a loop inside a loop). Space O(n) for the L row (and the P row of predecessors if you keep one). Keeping P to rebuild the answer does not change either.

One LIS is 2, 3, 6, 9. Starting at 7 instead gives 2, 3, 6, 7, which is also correct.

Section 3: Edit distance

3A Plain English: what edit distance means

  1. The edit distance between two words is the smallest number of single-letter changes that turns the first word into the second.
  2. There are three kinds of change, and each costs 1: insert a letter, delete a letter, or replace one letter with another. Keeping a letter that already matches is called a match and costs 0.
  3. Example: CAT to CUT is 1, because you replace A with U.
  4. The DP table is a grid. The first word goes down the side (rows), the second word goes across the top (columns), and each has an extra "empty" row and column at the start. A box says "the edit distance between the first part of word 1 up to this row, and the first part of word 2 up to this column". The answer is the bottom-right box.

3B Fast steps for each edit distance question type

Case A: "What goes in the first row and first column?" (the base case). Count up from 0: 0, 1, 2, 3, …. Why: turning nothing into 3 letters needs 3 inserts, and turning 3 letters into nothing needs 3 deletes.

Case B: "What number goes in this box?" Colour key: up is the box above, left is the box to the left, diagonal is the box up and to the left.

  1. Read off the three neighbours: up, left and diagonal.
  2. Work out three numbers: up plus 1 (a delete), left plus 1 (an insert), and diagonal plus 0 if the row letter and column letter are the same, or plus 1 if they are different (a match or a replace).
  3. Write the smallest of the three.
  4. Shortcut: if the two letters are the same, the answer is just the diagonal number (it can never be beaten).

Case C: "What is the edit distance of these two words?" Fill the grid row by row with Case B and read the bottom-right box. For very short words you can often see it directly: count the letters you would change.

Case D: "Which edit sequence is optimal?" Any list of changes is correct if its number of changes equals the bottom-right box and it really produces the second word.

Case E: "Running time and space?" For words of length m and n, the grid has (m + 1) times (n + 1) boxes and each box is 3 quick checks, so time O(mn) and space O(mn).
