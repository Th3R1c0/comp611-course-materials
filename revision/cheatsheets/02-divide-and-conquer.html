Start here: words and symbols

[DC-0] Glossary

Recursive = a function that calls itself on a smaller piece. Each smaller piece is a subproblem.

Sorting the left half of a list is a subproblem of sorting the whole list, and the function sorts it by calling itself.

Base case = the size where it stops splitting and answers directly.

A list of 1 item is already sorted, so merge sort just returns it. Without a base case the function would call itself forever.

T(n) = steps for input size n. T(n/2) = steps for half the size. Recurrence = T(n) written using a smaller T.

Read T(n) = 2T(n/2) + n as "the time for n is two half-size jobs plus n extra steps".

⌊x⌋ = round down. log_b a = what power of b gives a. log₂ n = how many halvings from n to 1.

⌊3.5⌋ = 3. log₃ 9 = 2 because 3 × 3 = 9. log₂ 8 = 3 because 8 → 4 → 2 → 1 is three halvings.

Powers: n⁰ = 1 (constant), n¹ = n, n^0.5 = √n, n^1.58 is between n and n².

The bigger the power, the faster it grows. A constant counts as power 0, which matters in the Master Theorem ([DC-8] step 3).

Section 1: the idea and the three algorithms

[DC-1] Divide, conquer, combine

Divide into smaller subproblems of the same kind. Conquer each by recursion (base case: solve directly). Combine the answers.

Why it helps: small problems are easy, and if splitting and joining are cheap, the total is much less than the obvious method.

"Base case" question → pick "the size at which it stops dividing and solves directly". Not the combine step.

Wrong options usually describe combining, or say it is "checked after the recursive calls return". The base case is checked first, before any recursion.

[DC-2] Binary search trace (list must be sorted)

mid = ⌊(low + high) ÷ 2⌋. Found if A[mid] = target. Smaller → high = mid − 1. Bigger → low = mid + 1. low > high → not found.e.g. [3,7,11,15,19,24,30] find 24: mid 3 → 15, bigger, low = 4 · mid 5 → 24 ✓

Write the positions (starting at 0 unless told otherwise) under the values first.

[3,7,11,15,19,24,30], target 24: mid=3 → 15, bigger → low=4; mid=5 → 24 found.

Each look throws away half → about log₂ n looks → Θ(log n). T(n) = T(n/2) + Θ(1).

For 16 items: sizes 16, 8, 4, 2, 1 = 5 looks = log₂ 16 + 1. For 1,000 items about 10 looks.

[DC-3] MERGE trace (combine step of merge sort)

Compare the two front items, take the smaller (tie → take L's) = 1 comparison. When one list is empty, copy the rest with no comparisons.e.g. L=[2,5,8] R=[3,7]: 2v3, 5v3, 5v7, 8v7, copy 8 → 4 comparisons

Both lists must already be sorted.

L=[2,5,8], R=[3,7]: 2v3, 5v3, 5v7, 8v7, then copy 8 → 4 comparisons, [2,3,5,7,8].

Merge sort: T(n) = 2T(n/2) + Θ(n) → Θ(n log n) in every case.

Why: merging costs about n at each level, and there are log₂ n levels of halving.

[DC-4] Fast exponentiation POWER(x, n)

n = 0 → return 1. Else y = POWER(x, ⌊n/2⌋). Even n → y × y. Odd n → x × y × y.Shortcut: halve and round down to 0 = the calls. Then work up from 1: even → square, odd → square × x.e.g. POWER(2,9): 9, 4, 2, 1, 0 (5 calls). Up: 1 → n1 odd 2·1·1 = 2 → n2 even 2·2 = 4 → n4 even 4·4 = 16 → n9 odd 2·16·16 = 512

The n values go down by halving (rounded down) until 0.

POWER(3,13): calls 13 → 6 → 3 → 1 → 0 (5 calls). Back up: 3, 27, 729, 3 × 729 × 729.

Naive: n − 1 multiplications, Θ(n). Fast: T(n) = T(n/2) + Θ(1) → Θ(log n).

For n = 1,000: 999 multiplications the naive way, about 10 calls the fast way.

Section 2: recurrences (from code, and recursion trees)

[DC-5] Write T(n) = a T(n/b) + f(n) from code

a = recursive calls that actually run. Trap: calls inside if / else → only one runs → a = 1.

Count the lines where the function calls itself. Binary search has two such lines, but only one runs each time, so T(n) = T(n/2) + Θ(1), not 2T(n/2).

n/b = size of each call's input (half → n/2, third → n/3).

Look at the range passed in: (lo, mid) is half the range (lo, hi).

f(n) = work outside the calls: simple lines → Θ(1); one loop over n → Θ(n); loop in a loop → Θ(n²).e.g. 2 calls on halves + 1 loop → 2T(n/2) + Θ(n) · calls in if/else + compare → T(n/2) + Θ(1) · 3 calls on thirds + loop in loop → 3T(n/3) + Θ(n²)

Same loop rules as week 1 [AA-12]. "Return the max of two", one comparison or one addition is Θ(1). Merging, counting, copying or printing all n items is Θ(n). Doing a Θ(n) loop twice is still Θ(n).

MAJORITY: 2 calls on halves + counting loop → 2T(n/2) + Θ(n).

[DC-6] Recursion tree

Draw it: 1 box at the top (level 0, size n). Under every box draw a boxes. Each level down, divide the size by b again.e.g. 2T(n/3), n = 27: level 0 one box 27 · level 1 two boxes 9 · level 2 four boxes 3 · level 3 eight boxes 1 (stop)

Think of each box as a worker with a job. The recurrence says how many smaller jobs each worker hands out (a) and how much smaller each one is (÷ b). The + f(n) part is only the worker's own effort, so you don't need it to count boxes or sizes.

Level i: aⁱ nodes, each of size n/bⁱ, each costing f(size). Level total = nodes × cost.e.g. 3T(n/4) + n², level 2: nodes aⁱ = 3² = 9 · size n ÷ bⁱ = n ÷ 4² = n/16

Level 0 is the first call. For 3T(n/4) + n²: level 2 has 3 × 3 = 9 nodes of size n/16, each costing (n/16)² = n²/256.

Height = log_b n levels. Leaves = n^(log_b a).e.g. 4T(n/2): leaves n^(log₂4) = n²

You divide by b until you reach 1, which takes log_b n steps. 4T(n/2) has n^(log₂4) = n² leaves: for n = 8, 3 levels and 4 × 4 × 4 = 64 = 8² leaves.

To get T(n) from the tree: compare how much work one whole level does with the level below it.• If every level does the same amount of work, the total is one level's work times the number of levels (log n).
• If each level does less work than the one above, the top level is most of the work, so T(n) = Θ(f(n)).
• If each level does more work than the one above, the bottom row (the leaves) is most of the work, so T(n) = Θ(n^(log_b a)).Quick check when f(n) is a power of n (n, n², n³…; call the power k): work out a ÷ bᵏ. If it is exactly 1, every level does the same work. If it is less than 1, the levels shrink. If it is more than 1, the levels grow.e.g. 2T(n/2) + n²: a = 2, b = 2, k = 2, so 2 ÷ 2² = 2 ÷ 4 = ½. Less than 1 → levels shrink → top wins → Θ(n²).e.g. 4T(n/2) + n: a = 4, b = 2, k = 1, so 4 ÷ 2 = 2. More than 1 → levels grow → leaves win → Θ(n^(log₂4)) = Θ(n²).e.g. 2T(n/2) + n: 2 ÷ 2 = 1 → every level does n work, log n levels → Θ(n log n).

Why: the total time is all the levels added up. If they keep getting smaller, the first one is bigger than all the rest put together (like n + n/2 + n/4 + … which never reaches 2n). If they keep getting bigger, the last row is the biggest. If they're all equal, you just multiply.

a ÷ bᵏ is what level 1 costs compared with level 0: level 1 has a boxes, each doing (n/b)ᵏ work, which is a ÷ bᵏ times the root's nᵏ.

[DC-7] Three methods for recurrences

Substitution = guess the answer, prove it by induction. Recursion tree = add each level, add the levels (makes the guess). Master = formula for aT(n/b) + f(n).

Induction means: show it works for small sizes, and show that if it works for the smaller sizes it works for n. Substitution is the most general; Master is the fastest when it applies.

Section 3: the Master Theorem

[DC-8] Master Theorem fast steps

1. Read a (calls, at least 1), b (shrink, more than 1), f(n). 2. p = log_b a (calculator: log a ÷ log b). 3. Power of f: n² → 2, n → 1, √n → 0.5, constant → 0.

p is the power of n that the leaves of the recursion tree add up to ([DC-6]).

f's power smaller than p → Case 1: Θ(n^p). Equal → Case 2: Θ(n^p log n). Bigger → Case 3: Θ(f(n)).e.g. 8T(n/2)+n²: p = log₂8 = 3; 2 < 3 → Case 1 Θ(n³) · 2T(n/2)+n: p = 1, equal → Case 2 Θ(n log n)

Why: n^p is the work at the leaves and f(n) is the work at the top. The bigger one wins. If equal, every level costs the same, so multiply by the log n levels.

8T(n/2)+n²: p=3, 2<3 → Θ(n³). 2T(n/2)+n: p=1, equal → Θ(n log n). T(n/2)+1: p=0, equal → Θ(log n). 7T(n/2)+n³: p≈2.807, 3 bigger → Θ(n³).

Case 3 also needs regularity: a·f(n/b) ≤ c·f(n), c < 1. For f = nᵏ: check a ÷ bᵏ < 1.

It means the work must shrink as you go down the tree. 7T(n/2)+n³: 7 ÷ 2³ = 7/8, less than 1, so it holds. For plain powers of n it always holds in Case 3.

[DC-9] When the Master Theorem does NOT apply

f differs from n^p by only a log (n log n or n/log n when p = 1) → does not apply (gap between cases).

The cases need a whole or decimal power of n between f and n^p. A log is smaller than any power, so it falls in the gap.

Course answer: 2T(n/2) + n log n → "does not apply". Only if the question says "extended Case 2" (logᵏ n): Θ(n log² n).

Also not: a < 1, b ≤ 1, number of calls depends on n, f negative, or Case 3 regularity fails.

The theorem only covers the exact shape aT(n/b) + f(n) with fixed numbers a ≥ 1 and b > 1.

Trap: f = log n or log² n with p > 0 does apply → Case 1.

Any log grows slower than any power of n, so it counts as smaller. Lab 2 (e): 3T(n/5) + log² n → p ≈ 0.682 → Θ(n^0.682).

[DC-10] Karatsuba vs school multiplication

School: 4T(n/2) + Θ(n) → p = 2 → Case 1 → Θ(n²). Karatsuba: 3T(n/2) + Θ(n) → p ≈ 1.585 → Case 1 → Θ(n^1.585).

Karatsuba uses an algebra trick so it needs 3 half-size multiplications instead of 4. n is the number of digits or bits, not the size of the number.

Fewer subproblems → smaller p → faster. Speed-up = n² ÷ n^1.585 (n = 10,000: about 46×).

The saving happens at every level, so the number of leaves drops from n² to n^1.585.

10,000² = 100,000,000. 10,000^1.585 ≈ 2,190,000. Divide: ≈ 46.
