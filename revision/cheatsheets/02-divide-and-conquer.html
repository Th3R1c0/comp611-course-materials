Start here: words and symbols

[DC-0] Glossary

A recursive function calls itself on a smaller piece of the problem. Each smaller piece is called a subproblem.

Sorting the left half of a list is a subproblem of sorting the whole list.

The base case is the size where the function stops splitting and answers directly.

A list of 1 item is already sorted, so merge sort just returns it. Without a base case the function would call itself forever.

T(n) means the time (number of steps) for an input of size n. T(n/2) means the time for an input half that size.

So 2T(n/2) means two jobs that are each half the size. It does not mean 2 times n.

A recurrence is an equation that gives T(n) using the time of smaller inputs.Example: T(n) = 2T(n/2) + n means the time for n is two half-size jobs plus n extra steps.

The extra steps are the work the function does itself, outside its recursive calls.

⌊x⌋ means round x down. log_b a means how many times you divide a by b to reach 1.Example: ⌊3.5⌋ is 3. log₂ 8 is 3, because 8 divided by 2 is 4, then 2, then 1, which is 3 divisions.

log_b a is read out loud as "log base b of a". It is the backwards question of a power: 2 multiplied by itself 3 times is 8, so log₂ 8 is 3.

Powers of n: n⁰ is 1 (a constant), n¹ is n, n² is n times n, n^0.5 is the square root of n. A decimal power like n^1.58 grows faster than n but slower than n².

The bigger the power, the faster it grows. A constant counts as power 0, which matters for the Master Theorem in [DC-8].

[DC-K] Colour key and calculator labels

When you substitute numbers in, each one has its own colour: a is the number of calls (in front of T), b is what n is divided by, k is the power of f(n), p is log_b a, and i is the level number. Each entry also says whether you need the calculator.

Read a recurrence like this: T(n) = 4T(n/2) + n¹. The blue number goes wherever a appears, the orange number wherever b appears, and so on.

Section 1: the idea and the three algorithms

[DC-1] Divide, conquer, combine

Divide the problem into smaller subproblems of the same kind. Conquer each one by calling the function on it (when it is small enough, the base case solves it directly). Combine the answers into one answer.

Why it helps: small problems are easy, and if splitting and joining are cheap, the total work is much less than the obvious method.

If a question asks what the base case is, pick the option that says it is the size where the algorithm stops dividing and solves the problem directly. It is not the combine step.

Wrong options usually describe combining, or say it is checked after the recursive calls return. The base case is checked first.

Binary search has no combine step: the answer from the one recursive call is the final answer.

[DC-2] Binary search trace (the list must be sorted)

No calculator needed Work out mid = ⌊(low + high) / 2⌋ and look at A[mid]. If it equals the target, you have found it. If the target is smaller, set high = mid − 1. If the target is bigger, set low = mid + 1. If low becomes bigger than high, the target is not in the list.Example: find 24 in [3, 7, 11, 15, 19, 24, 30]. First mid is position 3, which holds 15. 24 is bigger, so low becomes 4. Next mid is position 5, which holds 24, so it is found.

Write the positions under the values first. Positions start at 0 unless the question says otherwise.

Each look throws away half of what is left, so it takes about log₂ n looks. That is Θ(log n), and the recurrence is T(n) = T(n/2) + Θ(1).

For 16 items the sizes go 16, 8, 4, 2, 1, which is 5 looks. For 1,000 items it is only about 10 looks.

[DC-3] MERGE trace (the combine step of merge sort)

No calculator needed Compare the front item of each list and take the smaller one (if they are equal, take the one from L). Each of these is one comparison. When one list is empty, copy the rest of the other list across with no more comparisons.Example: L = [2, 5, 8] and R = [3, 7]. Compare 2 with 3, then 5 with 3, then 5 with 7, then 8 with 7. R is now empty, so copy 8 across. That is 4 comparisons, giving [2, 3, 5, 7, 8].

Both lists must already be sorted before merging.

Merge sort has the recurrence T(n) = 2T(n/2) + Θ(n), which gives Θ(n log n) for every input.

Why: merging costs about n steps on every level, and there are log₂ n levels of halving.

[DC-4] Fast exponentiation POWER(x, n)

If n is 0, return 1. Otherwise work out y = POWER(x, ⌊n/2⌋). If n is even, return y times y. If n is odd, return x times y times y.

x to the power n means x multiplied by itself n times, for example 2⁵ = 2 × 2 × 2 × 2 × 2 = 32.

Shortcut: keep halving n and rounding down until you reach 0. Each number in that list is one call. Then start from 1 at the bottom and work back up the list: when n is even, square the answer so far; when n is odd, square it and then multiply by x.Example: POWER(2, 9). The list is 9, 4, 2, 1, 0, which is 5 calls. Working up: start at 1. n = 1 is odd, so 2 × 1 × 1 = 2. n = 2 is even, so 2 × 2 = 4. n = 4 is even, so 4 × 4 = 16. n = 9 is odd, so 2 × 16 × 16 = 512.Calculator To check the final answer, type x^n: 2^9 = 512. To list the calls, keep dividing by 2 on the calculator and drop anything after the decimal point.

Why it works: 2⁹ is 2 times 2⁴ times 2⁴. Half of 9 rounds down to 4, and the lost 2 gets multiplied back in.

The normal way needs n − 1 multiplications, which is Θ(n). The fast way has the recurrence T(n) = T(n/2) + Θ(1), which is Θ(log n).

For n = 1,000 that is 999 multiplications the normal way, but only about 10 calls the fast way.

Section 2: recurrences (from code, and recursion trees)

[DC-5] Write T(n) = a T(n/b) + f(n) from code

No calculator needed a is the number of recursive calls that actually run. Trap: if the calls are inside an if and an else, only one of them runs, so a is 1.

Count the lines where the function calls itself. Binary search has two such lines, but only one runs each time, so its recurrence is T(n) = T(n/2) + Θ(1), not 2T(n/2).

n/b is the size of the input each call gets. If each call gets half, write n/2. If each gets a third, write n/3.

Look at the range passed in: (lo, mid) is half of the range (lo, hi).

f(n) is the work done outside the recursive calls. Only simple lines (a compare, an add, a return) give Θ(1). One loop over the n items gives Θ(n). A loop inside a loop gives Θ(n²).Example: two calls that both run, each on half, plus one loop over n, gives 2T(n/2) + Θ(n).Example: two calls inside an if and an else, plus a compare, gives T(n/2) + Θ(1).Example: three calls on thirds, plus a loop inside a loop, gives 3T(n/3) + Θ(n²).

These are the same loop rules as week 1 [AA-12]. Doing a Θ(n) loop twice is still Θ(n).

[DC-6] Recursion tree

How to draw it: draw 1 box at the top for the first call (this is level 0, size n). Under every box draw a boxes. Each time you go down a level, divide the size by b again. Stop when the size reaches 1.Example: 2T(n/3) with n = 27. Level 0 is one box of size 27. Level 1 is two boxes of size 9. Level 2 is four boxes of size 3. Level 3 is eight boxes of size 1, so it stops.

Think of each box as a worker with a job. a is how many smaller jobs each worker hands out, and b is how much smaller each job is. The + f(n) part is the worker's own effort, so you do not need it to count boxes or sizes.

At level i there are a multiplied by itself i times boxes, and each box has size n divided by b, i times. Each box costs f of its size, and a level's total is the number of boxes times the cost of one box.Example: T(n) = 3T(n/4) + n², level 2. Step 1: read off a = 3, b = 4, i = 2. Step 2: boxes = a to the power i = 3^2 = 9. Step 3: size = n divided by (b to the power i) = n ÷ 4^2 = n/16.Calculator Type a^i for the boxes (3^2 = 9) and b^i for what n is divided by (4^2 = 16).

Level 0 is the first call at the top.

The tree is log_b n levels tall. The number of leaves (boxes on the bottom row) is n to the power log_b a. Look up a and b in the match table [DC-M] to get that power.Example: 4T(n/2). Step 1: a = 4, b = 2. Step 2: p = log 4 ÷ log 2 = 2 (calculator, or the match table). Step 3: leaves = n^2 = n².

Check with n = 8: the size goes 8, 4, 2, 1, which is 3 levels down. Each level multiplies the boxes by 4, so 4 × 4 × 4 = 64 leaves, and 8² is 64.

To get T(n) from the tree, compare the work of one whole level with the level below it. If every level does the same work, T(n) is one level's work times log n. If each level does less work than the one above, the top level is most of the work, so T(n) = Θ(f(n)). If each level does more work, the bottom row is most of the work, so T(n) = Θ(n to the power log_b a).Calculator Quick check when f(n) is a power of n: Step 1: read off a, b and k (the power of f). Step 2: type a ÷ b^k. Step 3: exactly 1 means the levels are the same, less than 1 means they shrink, more than 1 means they grow.Example: 2T(n/2) + n². Type 2 ÷ 2^2 = 0.5. Less than 1, so the levels shrink, the top wins, and T(n) = Θ(n²).Example: 4T(n/2) + n¹. Type 4 ÷ 2^1 = 2. More than 1, so the levels grow, the leaves win, and T(n) = Θ(n²).Example: 2T(n/2) + n¹. Type 2 ÷ 2^1 = 1, so every level does n work. There are log n levels, so T(n) = Θ(n log n).

Why: the total time is all the levels added up. If they keep shrinking, the first level is bigger than all the rest together (n + n/2 + n/4 and so on never reaches 2n). If they keep growing, the bottom row is the biggest. If they are all equal, you multiply.

[DC-7] Three methods for solving recurrences

No calculator needed The substitution method guesses the answer and then proves it by induction. The recursion tree method adds up each level and then adds up the levels (it is often used to make the guess). The Master Theorem is a formula for recurrences shaped like aT(n/b) + f(n).

Induction means showing it works for small sizes, then showing that if it works for the smaller sizes it also works for n. Substitution is the most general method. The Master Theorem is the fastest when it applies.

Section 3: the Master Theorem

[DC-8] Master Theorem fast steps

Calculator: yes, for step 2 Step 1: read off a (the number of calls, at least 1), b (what n is divided by, more than 1) and f(n) (the extra work). Step 2: type log a ÷ log b to get p (or use the match table [DC-M]). Step 3: find k, the power of f(n). The power of n² is 2, the power of n is 1, the power of the square root of n is 0.5, and a constant like 1 has power 0.

p is the power that the leaves of the recursion tree add up to ([DC-6]).

Step 4: compare k with p. If k is smaller than p, it is Case 1 and T(n) = Θ(n^p). If they are equal, it is Case 2 and T(n) = Θ(n^p log n). If k is bigger, it is Case 3 and T(n) = Θ(f(n)).Example: 8T(n/2) + n². Step 2: log 8 ÷ log 2 = 3. Step 3: k = 2. Step 4: 2 is smaller than 3, so Case 1 and T(n) = Θ(n³).Example: 2T(n/2) + n¹. Step 2: log 2 ÷ log 2 = 1. Step 3: k = 1. Step 4: equal, so Case 2 and T(n) = Θ(n log n).Example: 1T(n/2) + 1. Step 2: log 1 ÷ log 2 = 0. Step 3: a constant has k = 0. Step 4: equal, so Case 2 and T(n) = Θ(log n).

Why: n^p is the work at the leaves and f(n) is the work at the top. Whichever is bigger wins. If they are equal, every level costs the same, so you multiply by the log n levels.

Case 3 also needs the regularity condition: the work must shrink going down the tree. When f(n) is n to the power k, check that a divided by b to the power k is less than 1.Calculator Example: 7T(n/2) + n³. Type 7 ÷ 2^3 = 0.875, which is less than 1, so it holds and T(n) = Θ(n³).

For plain powers of n it always holds in Case 3, so you only need to say it.

[DC-9] When the Master Theorem does NOT apply

No calculator needed It does not apply when f(n) is different from n^p by only a log, for example n log n or n divided by log n when p is 1. This is called a gap between the cases.Course answer: 2T(n/2) + n log n does not apply. Only if the question mentions the extended Case 2 (with log to the power k) is the answer Θ(n log² n).

The cases need a whole or decimal power of n between f(n) and n^p. A log is smaller than any power, so it falls in the gap.

It also does not apply when a is less than 1, when b is not more than 1, when the number of calls depends on n, when f(n) is negative, or when the Case 3 regularity condition fails.

The theorem only covers the exact shape aT(n/b) + f(n) with fixed numbers a and b.

Trap: if f(n) is log n or log² n and p is more than 0, the theorem does apply. It is Case 1.Example from lab 2: 3T(n/5) + log² n. p is about 0.682, so T(n) = Θ(n^0.682).

Any log grows slower than any power of n, so it counts as smaller than n^p.

[DC-10] Karatsuba compared with school multiplication

School multiplication is 4T(n/2) + Θ(n). p is 2, so it is Case 1 and Θ(n²). Karatsuba is 3T(n/2) + Θ(n). p is about 1.585, so it is Case 1 and Θ(n^1.585).

Karatsuba uses an algebra trick so it needs 3 half-size multiplications instead of 4. Here n is the number of digits or bits, not the size of the number.

Fewer subproblems give a smaller p, so the algorithm is faster.Calculator Speed-up: Step 1: type n^2 (10000^2 = 100,000,000). Step 2: type n^1.585 (10000^1.585 = about 2,187,000). Step 3: divide the first by the second, which is about 46. So Karatsuba is about 46 times faster.

10,000² is 100,000,000 and 10,000^1.585 is about 2,190,000. 100,000,000 divided by 2,190,000 is about 46. The saving happens on every level, so the number of leaves drops from n² to n^1.585.
