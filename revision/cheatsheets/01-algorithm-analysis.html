Start here: words and symbols

[AA-0] Glossary: every word used on this sheet

An algorithm is a list of exact steps that turns an input into an output.

A recipe is an algorithm: ingredients go in (input), a cake comes out (output). In this course the input is usually a list of numbers and the output is, for example, the list sorted.

The input size, written n, is how much data the algorithm is given.

If you sort a list of 1,000 numbers, n = 1,000. We describe everything in terms of n so we can ask what happens as the data gets bigger.

An elementary operation (also called a step) is one basic action that the computer does in a fixed amount of time.

Adding two numbers, comparing two numbers, or storing a value in a variable are each one step. See [AA-3] for the full list.

The step count is the total number of steps an algorithm performs on one input.

If an algorithm adds up a list of 10 numbers with one addition per number, its step count is about 10. The step count is how this course measures speed.

Running time means the step count, not the number of seconds.

So when a question says "running time", think "how many steps". [AA-2] explains why.

Time complexity is a rule (a formula in n) that tells you the step count for any input size.

For example, "2n + 1" is a time complexity: for n = 10 it predicts 21 steps, for n = 100 it predicts 201 steps.

The worst case is the input of a given size that needs the most steps. The best case needs the fewest. The average case is the typical amount.

Two lists of the same length can take different amounts of work. [AA-4] explains with an example.

Space (memory) is how much storage the algorithm uses while it runs. Auxiliary space means the extra storage it creates for itself, not counting the input.

"Auxiliary" just means "extra" or "helper". See [AA-5].

Pseudocode is code written in a simple, half-English style that isn't any real programming language.

It's how the lecture and exam show algorithms, e.g. for i = 1 to n. [AA-12] shows how to read it.

A term is one piece of a formula joined by + or −, together with its number: in 3n² + 5n + 2 the terms are 3n², 5n and 2.

See [AA-7] for how to find the fastest-growing term.

A constant is a fixed number that never changes (like 5 or 100). A variable can change. Here n is the variable.

c and n₀ in topic 3 are constants: you pick them once and they stay fixed. See [AA-9].

A growth rate describes how fast the step count grows as n gets bigger. A bound is a limit on that growth: a ceiling, a floor, or both.

Big-O, Big-Ω and Big-Θ ([AA-6]) are the three kinds of bound. A tight bound is the exact growth rate, written with Θ.

[AA-0s] Symbol key

T(n) or f(n) means "the number of steps for an input of size n".

Read the brackets as "for". T(n) = 2n + 1 means: for n = 10, T = 2×10 + 1 = 21 steps.

n² means n × n, n³ means n × n × n, and 2ⁿ means 2 multiplied by itself n times.

For n = 10: n² = 100, n³ = 1,000, 2ⁿ = 1,024. For n = 20: n² = 400, n³ = 8,000, 2ⁿ ≈ 1,000,000.

log n is how many times you can halve n before you reach 1.

8 → 4 → 2 → 1 is three halvings, so log 8 = 3. A million needs only about 20 halvings. The little number under log (log₂, log₁₀) is the base, and in this course it never changes the answer.

n log n means n multiplied by log n.

For n = 8: 8 × 3 = 24. It's a bit more than n but much less than n².

≤ means "at most" and ≥ means "at least".

"Steps ≤ 10n" means the steps never go above 10 times n.

c and n₀ are numbers you choose when proving a bound: c is a multiplier and n₀ ("n-nought") is the starting point.

See [AA-9] for how to choose them.

Θ(1) means "constant": the amount stays the same however big n gets.

Using 3 counter variables is Θ(1) because it's still 3 whether n is 10 or 10 million.

Topic 1 · The RAM model and what an algorithm is

[AA-1] Properties of an algorithm

An algorithm must have well-defined inputs: the data it's given before it starts.

Example: the list of numbers to sort.

It must have well-defined outputs: the result it produces when it finishes.

Example: the same numbers in sorted order.

Finiteness means it always stops after a limited number of steps.

A process that could loop forever is not an algorithm.

Definiteness means every step is clear, precise and has only one meaning.

"Add a bit of salt" is not definite. "Add 5 g of salt" is.

Effectiveness means every step is simple enough to actually carry out in reasonable time.

"Find the best answer by magic" is not effective.

[AA-2] The RAM model: why we count steps instead of seconds

The RAM (Random Access Machine) model measures running time by counting elementary operations, with each one costing 1.

It imagines a simple computer that does one thing at a time and can reach any spot in memory in the same time.

Why: seconds depend on the machine, the programming language and what else is running, but the step count is the same on every computer.

So the step count describes the algorithm itself, which lets us compare two algorithms fairly before we even write the code.

Trap: timing one run on a laptop does not tell you the complexity.

It depends on that laptop, a single measurement can't show how the time grows as n grows, and you don't know whether that input was a best or worst case.

[AA-3] What counts as one step (an elementary operation)

One step: arithmetic (+ − × ÷ %), a comparison (== != < >), storing a value in a variable, reading or writing one array item A[i], a return.

A[i] means "the item at position i in the list A". Each of these takes a fixed amount of time however big the input is.

Not one step: anything whose work grows with n, such as sorting a whole list, searching a list, or a loop that goes through n items.

Sorting n numbers takes many steps, and more for bigger n, so it can never count as a single elementary operation.

[AA-4] Best, worst and average case

Different inputs of the same size can need different numbers of steps.

Looking for a name in a list of 10: if it's first you need 1 check, if it isn't there you need 10.

The worst-case time complexity is a rule that gives, for each size n, the step count of the slowest input of that size.

It's the guarantee: the algorithm will never be slower than this. It's the one people care about most.

The best case is the fastest input of that size, and the average case is the average over all inputs of that size.

The average needs an assumption about how likely each input is, so it's harder to work out.

[AA-5] Space complexity and auxiliary space

Space complexity is the most memory the algorithm uses at any one moment, as a rule in n.

Like time complexity, but counting storage instead of steps.

Auxiliary space is only the extra memory the algorithm creates. The input itself is not counted.

If the input is a list of n numbers and the algorithm only creates counters i, j and k, its auxiliary space is 3 values whatever n is, which is constant: Θ(1).

If the algorithm creates a new list of size n, its auxiliary space is Θ(n).

For example, copying the input into a new array.

Topic 2 · Big-O, Big-Ω and Big-Θ

[AA-6] The three kinds of bound, in English

O = at most (a ceiling). Read "f = O(n²)" as "f grows no faster than n²".

Like a speed limit: "at most 100 km/h" is obeyed by a car doing 50. So a slower function always fits under a faster ceiling. 5n + 3 = O(n²) is TRUE because n is slower than n².

Ω = at least (a floor). Read "f = Ω(n)" as "f grows at least as fast as n".

Every algorithm is Ω(1), because it always grows at least as fast as a constant.

Θ = exactly. Read "f = Θ(n)" as "f grows at exactly the same rate as n". It's only true if the ceiling and floor are the same.

If you only know "O(n²) and Ω(n)", the ceiling and floor are different, so no single Θ follows.

The = sign here does not mean equal. It means "fits this description".

"5n + 3 = O(n²)" doesn't claim 5n + 3 equals n². It claims 5n + 3 fits the description "grows at most as fast as n²".

A tight bound means Θ: the exact growth rate. Find it with [AA-7].

Multiple choice often asks for the "tight asymptotic bound".

[AA-7] Finding the growth rate of a function

A term is each piece joined by + or −, including its number. 4n² + 9n log n + 100 has three terms: 4n², 9n log n and 100.

The number in front (the 4 in 4n²) is part of the term. A term with no n at all (like 100) is a plain constant.

Step 1: cross out the number in front of every term. Step 2: find each n-part in the growth order [AA-10]. Step 3: the one furthest right is the growth rate.

4n² + 9n log n + 100 → n², n log n, 1. In the order 1 → log n → n → n log n → n² → n³ → 2ⁿ, n² is furthest right, so it's Θ(n²). Check with n = 1,000: 4,000,000 vs about 90,000 vs 100.

Why we drop the number in front: 100n and n both double when n doubles, so they grow the same way.

The number only changes speed on a particular machine, not how the work grows.

The base of a log doesn't matter: log₁₀ n and log₂ n are both Θ(log n).

Changing the base just multiplies by a fixed number, and fixed numbers are dropped.

[AA-8] Judging any O / Ω / Θ statement (fast steps)

Step 1: find the growth of the left side with [AA-7]. Step 2: compare it with what's in the brackets: is the bracket the same, slower or faster?

Example: 10n = Θ(n). Left: drop the 10 to get n. Bracket: n. They're the same.

O is true if the bracket is the same or faster. Ω is true if the bracket is the same or slower. Θ is true only if it's the same.

10n = Θ(n): same, so TRUE. n = Ω(n²): the bracket n² is faster, so a floor of n² is too high, FALSE. n³ = O(n²): the bracket is slower, so the ceiling is too low, FALSE.

Trap: 5n − 2 = O(n²) is TRUE (a high ceiling is allowed), but 5n − 2 = Θ(n²) is FALSE (its exact rate is n).

Say it in English first. "At most as fast as n²" is true, "exactly as fast as n²" is false.

Trap: "an O(n²) algorithm takes quadratic time on every input" is FALSE.

O is only a ceiling. Insertion sort is O(n²) but linear on a sorted list ([AA-13]).

Topic 3 · Proving bounds with c and n₀

[AA-9] What c and n₀ mean

A constant is a fixed number that never changes once you pick it. c and n₀ are constants. n is the variable: the input size, which keeps growing.

That difference is the key to the "impossible" questions: n keeps growing, c is stuck.

c = how many copies of the bracket the ceiling (or floor) uses. It always goes on the right, multiplying the bracket.

Why c exists: 5n ≤ n is false, but 5n and n grow the same way. Allowing c copies (5n ≤ 5 × n) lets us ignore the number in front, which is exactly the "drop the number" rule.

n₀ = the first input size to check. You replace every n with it, on both sides. It is not a multiplier.

c = 14, n₀ = 10 means: put n = 10 into the function, and compare with 14 × 10².

Picture: the function's line must stay under the ceiling c × n² (or over the floor) from n₀ onwards.

[AA-9b] Fast steps for every topic 3 question

Step 1, always unpack: left = the function. Right = c × (what's in the brackets). O → ≤, Ω → ≥.

"6n² + 3n + 2 is O(n²)" → 6n² + 3n + 2 ≤ c × n². "5n = O(1)" → 5n ≤ c × 1 (the 1 is hiding in the brackets!).

Find c for O (ceiling): add up all the numbers, n₀ = 1. Then find that pair in the options.

6n² + 3n + 2 → 6 + 3 + 2 = 11, so c = 11, n₀ = 1. Check at n = 1: left 11, right 11 × 1 = 11, 11 ≤ 11 ✓.

Find c for Ω (floor): c = the front number of the biggest term, n₀ = 1.

4n² + n + 9 → c = 4. A bigger c (5, 14) may pass at n = 1 but fails at n = 100.

Checking options: put c on the right, replace n with n₀, compare. Then check n = 100 too.

For O, a c that's not bigger than the front number fails when anything is added: 2n + 6 ≤ 2n is never true, so c = 2 fails (at n = 50: 106 ≤ 100 ✗).

"Why can't it be proven?" If the bracket is slower than the function, it's impossible. Pick "n keeps growing but c is fixed".

5n = O(1) → 5n ≤ c × 1. 1 is slower than n. Whatever c you pick, n passes it. Same for 2n² = O(n): 2n² ≤ c × n becomes 2n ≤ c, and 2n keeps growing.

Minus sign, find the smallest n₀: put in each option smallest first. The first one that passes is the answer.

n² − 10n ≥ n²/2 with options 2, 5, 10, 20: n = 10 gives 0 ≥ 50 ✗, n = 20 gives 200 ≥ 200 ✓, so it's 20. (n²/2 means n × n ÷ 2.)

Topic 4 · Growth order and timing tables

[AA-10] Growth order, slowest to fastest

1 < log n < n < n log n < n² < n³ < 2ⁿ < n!

For n = 1,000: log n ≈ 10, n log n ≈ 10,000, n² = 1,000,000, n³ = 1,000,000,000, and 2ⁿ is too big to write. n! ("n factorial") is 1 × 2 × 3 × … × n.

"Which is faster for very large n?" Cross out the numbers in front, find both on the growth order, and the one further left (slower growing) takes fewer steps.

A = 0.001n² vs B = 100 n log n → n² vs n log n. n log n is further left, so B takes fewer steps for big n, even though 100 looks bigger than 0.001. The numbers only matter for small n.

[AA-11] Reading a timing table

Step 1: check the n values double (500 → 1,000 → 2,000). Step 2: divide each time by the time before it. Do not divide the n values.

Dividing the n values (1,000 ÷ 500 = 2) only confirms that n doubled. The answer is in the times: 2 s, 16 s, 128 s → 16 ÷ 2 = 8, 128 ÷ 16 = 8.

Step 3: match the time ratio. About 1 (adds a little) → log n · 2 → n · a bit over 2 → n log n · 4 → n² · 8 → n³.

Why: if work is n², doubling n gives 2 × 2 = 4 times the work. For n³ it's 2 × 2 × 2 = 8. So a ratio of 8 means n³.

For log n, doubling n only adds a small fixed amount: 1.0 s → 1.1 s → 1.2 s.

Doubling n adds just one more halving step.

"n gets k times bigger. How long now?" k = new n ÷ old n. Then look at the brackets: multiply the time by k for n, k × k for n², k × k × k for n³.

Θ(n²) takes 1 s at n = 10,000. At 30,000: k = 3, and it's n², so 3 × 3 = 9, giving 9 s. (3 s would only be right for Θ(n).)

For 2ⁿ, adding just 1 to n doubles the time.

That's why exponential algorithms become hopeless so quickly.

Topic 5 · Counting steps from pseudocode

[AA-12] How to count

for i = 1 to n means i takes the values 1, 2, 3, … up to n, so the loop goes round n times.

"for i = 1 to 4" runs with i = 1, 2, 3, 4: four rounds.

Counting lines: a line outside every loop runs 1 time. A line inside the loop runs n times. The for line itself runs n + 1 times.

The for line checks "is i still ≤ n?" before every round (n times) plus one extra time when the answer is no and it stops. You can tell a line is inside the loop because it's indented under it.

Example: 1 x = 0 · 2 for i = 1 to n · 3   x = x + A[i] · 4 return x → 1 + (n + 1) + n + 1 = 2n + 3, which is Θ(n).

Line 1 is outside (1), line 2 is the for line (n + 1), line 3 is inside (n), and line 4 is outside (1).

For growth only, find the line inside the deepest loop and count how often it runs. Nested loops (one inside another) multiply. Loops one after another add.

Two separate loops to n: n + n = 2n, which is Θ(n). One loop to n inside another: n × n = Θ(n²).

Pattern table, matching the loop shape:
Loop shapeTimesGrowth
for i = 1 to nnΘ(n)
for i…n with for j = 1 to n insiden × nΘ(n²)
for i…n with for j = i+1 to n insiden(n−1)/2Θ(n²)
for i…n with for j = 1 to i insiden(n+1)/2Θ(n²)
three nested loops to nn × n × nΘ(n³)
i = i / 2 or j = j * 2 looplog nΘ(log n)
halving loop inside a loop to nn × log nΘ(n log n)
loop to n, then a separate loop to n2nΘ(n)

j = i + 1 to n checks each pair once. For n = 5: 4 + 3 + 2 + 1 = 10, and 5 × 4 ÷ 2 = 10. Half of n² is still Θ(n²), because the number in front is dropped. A loop that halves runs log n times, because log n is how many halvings it takes to reach 1 ([AA-0s]).

Shortcut: 1 + 2 + 3 + … + n = n(n + 1)/2.

Pair the first with the last: 1 + n, 2 + (n − 1), and so on. Each pair adds to n + 1, and there are n/2 pairs. 1 + … + 10 = 10 × 11 ÷ 2 = 55.

Topic 6 · Best and worst cases of known algorithms, and Fibonacci

[AA-13] Algorithms to know

Linear search checks items one by one. Best case: the target is first, Θ(1). Worst case: the target is missing, Θ(n), with 2n + 1 steps.

If it's missing, every item must be checked: n loop steps + n comparisons + 1 return.

Insertion sort takes each item and slides it left into place, like sorting cards in your hand.

Each slide of one item by one place is called a shift.

Insertion sort best case: the list is already sorted, so there are 0 shifts, but it is still Θ(n), not Θ(1).

It still has to look at each of the n items once to check it's in place.

Insertion sort worst case: the list is in reverse order, so there are 1 + 2 + … + (n − 1) = n(n − 1)/2 shifts, Θ(n²).

For a reversed list of 5: 4 × 5 ÷ 2 = 10 shifts.

For any list, insertion sort's shifts = the number of pairs in the wrong order (a bigger number before a smaller one).

[3, 1, 2]: (3,1) wrong, (3,2) wrong, (1,2) fine, so 2 shifts.

Merge sort is Θ(n log n) on every input, so its best and worst cases are the same.

It always splits and merges in exactly the same way, so the order of the input doesn't matter.

Binary search needs a sorted list. It looks at the middle and throws away the half that can't contain the target. Worst case Θ(log n).

Halving each time means log n steps ([AA-0s]).

If a loop can stop early (an early return), there's no single Θ for all inputs. Say O(worst) and Ω(best).

The time then depends on the actual values, not just n. Without the early return the loop always runs to the end and one Θ works.

[AA-14] Fibonacci case study

Fibonacci numbers: each is the sum of the two before it: 0, 1, 1, 2, 3, 5, 8, 13 …

The lecture uses it to compare four algorithms for the same problem.

Naive recursion is exponential (about 1.618ⁿ, written O(2ⁿ)) because it recalculates the same smaller numbers again and again.

Recursion itself isn't the problem. Binary search is recursive and only takes log n steps.

Storing answers (memoisation) or using a simple loop takes O(n). Matrix exponentiation takes O(log n).

Memoisation means writing each answer down the first time so you never work it out twice.
