Start here: words and symbols

[GR-0] Glossary

A graph is dots (vertices, also called nodes) joined by lines (edges). V is how many vertices, E is how many edges (the lecture writes |V| and |E|).

The bars in |V| just mean "how many". A graph with 5 vertices and 7 edges has V = 5 and E = 7.

Directed means each edge is one way (an arrow). Undirected means each edge works both ways. Weighted means each edge has a number, its weight, written w(u, v).

w(A, B) = 6 means the edge from A to B costs 6. In a directed graph that says nothing about going from B to A.

A path follows edges in a row. Its cost is the weights added up. Its length, or number of hops, is how many edges it uses.

A to B (weight 4) then B to D (weight 4) has cost 8 and length 2 hops. A cycle is a path that ends where it started.

dist[v] is the best distance from the source s to v found so far. prev[v] is the vertex just before v on that route. ∞ means "not reached yet". NIL means "nothing".

The source s is the start vertex. At the start dist[s] = 0, every other dist is ∞, and every prev is NIL.

Dense means lots of edges, so E is close to V². Sparse means few edges, so E is close to V.

With 100 vertices, a dense graph has thousands of edges and a sparse one has a few hundred.

Section 1: storing a graph

[GR-1] Adjacency matrix

A square table of every vertex against every vertex. The row is where the edge starts and the column is where it ends. Write the weight if the edge exists, ∞ if not, and 0 on the diagonal.Example: edges A to B is 6 and A to C is 2, so row A reads 0, 6, 2, ∞, ∞ and row B, column A is ∞.

For a graph with no weights, write 1 for an edge and 0 for no edge.

Undirected: every edge goes in two boxes, so the table is a mirror image across the diagonal. To count edges, count the 1s and halve it.Example: a 4 by 4 undirected matrix with eight 1s has 8 divided by 2 = 4 edges.

The edge between A and C is written in row A column C, and again in row C column A. For a directed matrix, count the weights and do not halve.

[GR-2] Adjacency list

Each vertex lists its (neighbour, weight) pairs for the edges that start there. Write a dash if none start there. Undirected edges appear in both ends' lists.Example: A: (B, 6), (C, 2). E: dash.

It only stores edges that exist, which is why it is small for sparse graphs.

Example: V = 5 and E = 7. The matrix uses 5 × 5 = 25 entries and the list uses 5 + 7 = 12.

Why the matrix checks an edge in one step: it jumps straight to row u, column v. The list must read u's neighbours one by one, and u could be joined to almost every vertex.

"Which is faster, O(V to the power 1.5) or O(E)?" It depends on the graph. Dense: E is about V², so V to the power 1.5 is faster. Sparse: E is about V, so E is faster.

Running times of graph algorithms depend on both V and E, so how many edges there are decides which wins.

Section 2: breadth-first search (BFS)

[GR-4] BFS trace with a queue

Queue starts as [s] with dist[s] = 0. Take the front vertex u. For each neighbour (alphabetical) never found before: dist = dist[u] + 1, prev = u, add to the back. Repeat until empty. The order taken off is the visit order.Example: edges A to B, A to C, B to D, C to D, C to E, D to F, E to F, start A. Take A, add B and C. Take B, add D. Take C, add E (D already found). Take D, add F. Order: A, B, C, D, E, F.

A queue is a waiting line: join at the back, leave from the front ("first in, first out"). Vertices already in the queue or already taken off are skipped. BFS finds vertices in rings: the layer number is the distance in edges.

[GR-5] BFS dist, prev and the path back

dist[v] is the layer number, which is the fewest edges from s. prev[v] is the vertex being taken off when v was first found.Example: D touches B and C. B was taken off first, so prev[D] = B.

Trap: when two vertices touch v, the one dequeued earlier wins. The later one sees v is already found.

Path: start at the target, follow prev back to s, then read it in reverse. Number of hops = dist[target].Example: prev[F] = D, prev[D] = B, prev[B] = A. Backwards F, D, B, A, so the path is A, B, D, F with 3 hops.

prev records how each vertex was first reached, so following it backwards always lands on s. The same steps rebuild a Dijkstra path.

[GR-6] BFS facts

Running time O(V + E) with an adjacency list (O(V²) with a matrix). Each vertex joins the queue at most once, and each edge is looked at once (directed) or twice (undirected).

With a matrix, finding a vertex's neighbours means reading a whole row of V boxes, for every vertex, so V times V.

BFS ignores weights: it finds the fewest edges, not the smallest total weight. A route with more but lighter edges can weigh less.Example: BFS path A, B, D, F weighs 4 + 4 + 4 = 12, but A, C, E, F weighs 1 + 2 + 1 = 4.

BFS counts every edge as 1. For weights use Dijkstra [GR-8].

Section 3: Dijkstra's algorithm

[GR-7] Relax the edge from u to v

Step 1: new = dist[u] + w(u, v). Step 2: if new is strictly smaller than dist[v], set dist[v] = new and prev[v] = u. If equal or bigger, change nothing. No calculator.Example: dist[a] = 4, w(a, b) = 3, dist[b] = 10. 4 + 3 = 7, which is smaller than 10, so dist[b] = 7 and prev[b] = a.

Blue is the start of the edge, orange is the edge weight, green is the end of the edge. Relaxing can only make dist smaller. A dist can be lowered many times until its vertex is confirmed.

[GR-8] Dijkstra trace (lazy deletion)

Start dist[s] = 0, others ∞, queue (s, 0). Take out the pair with the smallest number. If its vertex is already confirmed it is stale: skip it. Otherwise confirm it and relax all its outgoing edges, adding (v, new dist) for each improvement. Repeat until the queue is empty.Example: lab graph from S. Take S (0): A gets 4, B gets 2. Take B (2): A becomes 3, C gets 7. Take A (3): C becomes 5, D gets 6. (A, 4) is stale. Take C (5): T gets 8. Take D (6). (C, 7) is stale. Take T (8). Order S, B, A, C, D, T.

Confirmed means final: that dist never changes again. The order goes by smallest dist, not by when a vertex was first seen. Every improvement after the first leaves one stale pair behind. Vertices never reached stay ∞. Ties can go either way.

Only works when every weight is 0 or more. Path and cost: follow prev back from the target, reverse it, and the cost is dist[target].Example: T, C, A, B, S reversed is S, B, A, C, T, and 2 + 1 + 2 + 3 = 8 = dist[T].

Adding the weights along the path is a quick check that the trace was right.

With numbers, put V and E into both and pick the smaller. Calculator: log₂ V = log(V) ÷ log(2).Example: V = 1,000 and E = 2,000. Array: 1,000,000. Heap: 3,000 × 10 = 30,000, so the heap wins.

There are V DeleteMin operations and at most E improvements. An array needs V steps to find the smallest; a heap needs about log V steps per operation. A priority queue is a to-do list that always hands back the smallest number first.

[GR-10] Negative edges and which algorithm to use

A negative edge can make Dijkstra wrong: it may confirm a vertex before the cheaper route through the negative edge is found.Example: S to A is 2, S to B is 4, B to A is −3. Dijkstra confirms A at 2, but S, B, A costs 4 − 3 = 1.

Dijkstra assumes a route can only get heavier as it goes. A negative edge breaks that, so a confirmed dist might not be final.
